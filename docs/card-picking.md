新塔罗流程：写下问题、选择牌阵 → 洗牌并展开牌堆 → 逐个牌位选择一张背面牌 → 选满后逐张翻开 → 阅读中文解读、带入绯月会话。

## 产品表达

按照用户最新决定，主界面移除正逆等概率说明、算法编号、结果ID和实现方式说明。保留影响体验的“包含逆位”选择、当前牌位、选牌进度和可展开的实际资料依据。不声称用户直觉提高预测准确率。概率及随机算法仅在工程文档中记录；用户主动询问规则时仍可如实说明。

## 实现与兼容

- 新界面通过原抽牌入口传入 `select_cards: true`。后端使用系统随机源洗匀整副78张牌，一次性决定每张方向，存入只在服务端读取的 `hidden_decks` 表；方向仍为独立各50%，关闭逆位时全部正位。
- 按用户点击的槽位索引提取实际卡牌，选择次序对应牌位次序。不是预先抽好三张再把任意点击映射到同一个结果。
- 未选满时公开结果只含总数、牌位和已选索引，不含整副牌的身份或方向；模型不能提前解读未完成的选择。选满后生成同版中文知识快照，删除未选牌堆内容。
- 每次选择包含 `slot` 和 `order`；事务校验当前进度。同一选择重放返回同一结果；不同选择争用同一牌位返回409，不多抽也不覆盖。刷新、重复开始请求和进程重启沿用同一个牌堆。
- 删除和过期会清除未选牌堆，旧结果ID／请求仍不能复活。账号隔离保持不变，导出不会包含隐藏牌堆。
- 旧客户端不传 `select_cards` 时仍兼容原来的一次抽牌；旧结果及原创签流程不变。
- SQLite schema版本升为4，增加一张表，不修改已有结果。首次打开版本低于4的数据库时生成 `buxi.db.pre-v4-*.bak`；旧的pre-v3备份仍保留。恢复步骤见 [run-v03.md](run-v03.md)。没有在本轮测试中迁移真实用户库。
